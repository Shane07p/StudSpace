# Database

PostgreSQL 16. Schema in `Backend/src/main/resources/schema.sql`, auto-applied on the **first** start of a fresh DB volume (it does not re-run on an existing database). Hibernate runs with `ddl-auto=validate` — it checks the schema matches the entities but never alters it.

All primary keys are **UUIDv4**, generated by Hibernate (`@GeneratedValue(strategy = GenerationType.UUID)`); the `DEFAULT gen_random_uuid()` in the schema is a fallback for manual inserts. Random ids mean ids can't be guessed/enumerated — see the ownership pattern in [backend.md](backend.md).

## Tables (7)

| Table | Purpose |
|-------|---------|
| `users` | Accounts (email/password + Google OAuth) and profile info |
| `user_handles` | Social / coding profile links (one user → many) |
| `semesters` | Academic semesters per user, with optional public share token |
| `courses` | Courses within a semester |
| `resources` | Study resources (link / notes / PDF) under a course or semester |
| `attendance_records` | Daily attendance per course |
| `timetable_slots` | Weekly class schedule per semester |

## Relationships (ER)

```
users ──1:many──▶ user_handles        (ON DELETE CASCADE)
users ──1:many──▶ semesters           (ON DELETE CASCADE)
semesters ──1:many──▶ courses          (ON DELETE CASCADE)
semesters ──1:many──▶ timetable_slots  (ON DELETE CASCADE)
semesters ──1:many──▶ resources        (semester_id, nullable — "uncategorized")
courses ──1:many──▶ resources          (course_id, nullable)
courses ──1:many──▶ attendance_records (ON DELETE CASCADE)
courses ──0..1──▶ timetable_slots      (course_id, ON DELETE SET NULL)
```

## Column reference

**users** — `id`, `username` (unique), `email` (unique), `password_hash` (null for OAuth-only), `google_sub` (unique), `full_name`, `college`, `branch`, `year`, `bio`, `profile_photo`, `cover_photo`, `created_at`, `updated_at`

**user_handles** — `id`, `user_id` →users, `platform`, `url`, `display_order`

**semesters** — `id`, `user_id` →users, `label`, `short_name`, `is_current`, `share_token` (unique, null = not shared), `created_at`

**courses** — `id`, `semester_id` →semesters, `code`, `name`, `instructor`, `credits` (default 3), `total_classes`, `created_at`

**resources** — `id`, `course_id` →courses (nullable), `semester_id` →semesters (nullable), `type` (`PYQ`/`NOTES`/`PLAYLIST`/`LINK`/`OTHER`), `title`, `url`, `notes`, `created_at`

**attendance_records** — `id`, `course_id` →courses, `date`, `status` (`PRESENT`/`ABSENT`/`CANCELLED`), `created_at`, **unique (`course_id`, `date`)** — one record per course per day (enables upsert)

**timetable_slots** — `id`, `semester_id` →semesters, `course_id` →courses (nullable), `day`, `start_time`, `end_time`, `room`, `created_at`

## Indexes

## Accessing the DB

Local or on the droplet, through the container (no exposed port):

```bash
docker compose exec db psql -U postgres -d studspace -c "SELECT username, email FROM users;"
```
